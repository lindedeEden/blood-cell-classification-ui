# ADR 0003：以「與舊版對照」證明功能與畫面相同

- 狀態：已採用（2026-10-25）

## 背景

改寫的要求是「功能、畫面、規則結果相同」。只靠人工比對無法涵蓋所有膠囊組合與操作順序。

## 決定

1. **規則對照**：`tools/legacy-capture/capture-domain.cjs` 以唯讀方式載入舊版程式，對 25 筆檢體跑進線判斷、853 個操作步驟、門檻修改、LIS 撤回等，把結果存成 `tests/parity/golden/domain.json`；`tests/parity/domain.test.ts` 讓新版跑同一組輸入並逐項比對。
2. **畫面對照**：`tools/visual/tour.mjs` 定義一套只依賴畫面元素的操作巡覽，新舊版各跑一次並逐張截圖比對（`tools/visual/compare.mjs`）。舊版的 CDN（Tailwind、Google 字型）以本機副本代替，確保比對條件相同。
3. **回歸測試**：同一套巡覽放進 `npm run test:e2e`，每個畫面記錄 DOM 指紋（與平台無關）並比對代表截圖。

## 結果

- 規則：輸出完全相同；唯一差異是舊版 LIS 撤回的錯誤（已修正，見 `CHANGES-FROM-LEGACY.md` B1）。
- 畫面：77 個畫面中 35 張完全相同，其餘為字型反鋸齒（約 0.005%）或已確認的修正。
- 重構時以 DOM 指紋把關：例如程式格式化工具曾改動 HTML 樣板的空白，指紋比對立即發現並已還原。

## 影響

- 模擬資料修改時（例：2026-10-25 補上前次 CBC），以舊版程式＋新資料重新產生標準答案，維持「同一份資料、新舊程式」的比對；新版新增、舊版沒有的欄位（`lis.prevReport.cbc`）在比對時另外驗證。

- 之後有意改變規則或畫面時，需更新對照基準（`--update-snapshots`），並在 `CHANGES-FROM-LEGACY.md` 記錄。
