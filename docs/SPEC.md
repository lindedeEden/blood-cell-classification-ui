## 1. 目標

用工程團隊習慣的技術與架構，**重新打造**同一套原型：

- **功能、畫面、規則結果與舊版完全相同**（使用者看不出差別）
- 程式架構、規則程式的寫法可以完全重新設計，以「好讀、好測、好移植到正式系統」為準
- 提交文件 2、3 依新程式重寫（規則文字不變）；文件 1 沿用

使用者：工程團隊（接手開發正式系統）、Eden（展示與可用性研究）。

## 2. 我的假設（請確認或修正）

1. 「畫面相同」＝ 版面、文字、顏色、按鈕位置、互動行為相同；不追求像素級完全一致（字型反鋸齒等細微差異容許）
2. 「規則結果相同」＝ 同樣的檢體與操作，產生相同的膠囊、清單歸屬、橫幅顏色、按鈕狀態、人員編輯值與 LIS 回寫內容
3. 模擬資料（25 筆檢體、細胞範例圖、可用性研究情境）內容不變，只換存放格式
4. 仍是**純前端原型**，沒有真正的後端；登入、LIS、AI 模型照舊用模擬
5. 建置後的成品**雙擊 HTML 就能開**（不需架伺服器），也能放 GitHub Pages
6. 瀏覽器：Chrome／Edge 最新版

## 3. 技術選擇

| 項目 | 選擇 | 理由 |
|---|---|---|
| 語言 | TypeScript 5.9（strict） | 型別檢查；檢體資料結構寫成型別，工程師一看就懂 |
| 建置 | Vite 8 | 多頁面建置、開發時即時預覽 |
| 樣式 | Tailwind CSS 3.4（本地建置，取代 CDN） | 與舊版同一套 class 與設定，畫面才會一樣；順便完成「上線前必做：Tailwind 改本地打包」 |
| 字型 | Inter、Material Symbols 改本地檔案 | 院內網路不能連外時也能正常顯示 |
| 單元測試 | Vitest | 規則測試（移植舊版 76 項） |
| 畫面測試 | Playwright | 新舊版逐頁截圖比對、操作流程測試 |
| 程式檢查 | ESLint（typescript-eslint）、Prettier | 統一風格 |

不用 React 等框架（已確認）：以 TypeScript 模組＋原生 DOM 實作，畫面 HTML 結構沿用舊版。

## 4. 能力地圖（模組與相依方向）

| 模組 | 負責 | 依賴 |
|---|---|---|
| `domain` | 型別：檢體、膠囊、流程狀態、門檻；**純函式規則 1～15** | — |
| `data` | 四個來源模擬資料、AI 模型模擬（進線合併的規則在 domain） | domain |
| `infra` | 瀏覽器儲存、模擬 API（登入、LIS 回寫）、登入與登出 | domain |
| `app` | 應用動作：簽核、改人工鏡檢、標記完成、LIS 撤回、門檻設定（呼叫 domain 規則、寫入 infra） | domain、data、infra |
| `ui` | 四個頁面、共用工具（跳脫、跳轉、字級） | app、infra、domain |
| `demo` | 使用教學、情境模擬測試（可整包移除） | app、ui |
| `pages` | 各頁進入點，組裝以上模組 | 全部 |

依賴只能往上，不能循環；`domain` 不碰畫面、不碰瀏覽器，可在 Node 直接測試。
建置順序：domain → data → infra → app → ui → demo。

## 7. 程式風格

- 規則寫成**純函式**，輸入檢體、輸出結果，不改傳入物件：

```ts
/** 規則 2：LIS 有「需推片確認」註記 → 需拉片確認；否則數位閱片 */
export function intakeRoute(spec: Specimen): 'Follow-up' | 'Digital Review' {
  return spec.lis.smearRequiredNote ? 'Follow-up' : 'Digital Review';
}
```

- 檔名 kebab-case；型別 PascalCase；函式動詞開頭
- 註解以中文寫「為什麼」；每條規則函式標註「規則 N」，與文件 2 對應
- 畫面程式不直接讀寫瀏覽器儲存，一律經 `infra/storage`
