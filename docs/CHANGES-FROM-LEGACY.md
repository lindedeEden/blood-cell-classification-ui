# 與舊版原型的差異

新版以 TypeScript 重新打造，**功能、畫面與規則結果與舊版相同**。以下是刻意不同的地方：Eden 確認過的規則／畫面調整、舊版的錯誤修正，以及不影響畫面的技術改善。

驗證方式見文末。舊版指 `血球分類軟體介面設計專案`（GitHub `blood-cell-classification-ui`，commit d0b87e9）。

---

## A. 經 Eden 確認的調整（2026-10-25）

| # | 項目 | 舊版 | 新版 | 影響範圍 |
|---|---|---|---|---|
| A1 | 判斷與回傳 LIS 用的數值（規則 4、14） | 規則寫「人員編輯結果與 AI 在任一留單項目不同才採用」，但程式把 WBC 也拿來比，實際上只要分析儀有 WBC 就一律採用；WBC 空白時，只改非留單項目（例 Band↔Segmented、NRBC）會回傳 AI 值，與報告畫面顯示的人員編輯值不同 | **有人員編輯值就一律採用**；回傳 LIS 的永遠是簽核時看到的數值 | 留單判斷結果完全不變；只有「WBC 空白＋只改非留單項目」時回傳 LIS 的數值不同 |
| A2 | 報告簽核頁直接用網址開啟（規則 6） | 可單獨開啟，已鎖定或已完成的檢體也能按「確認並簽核」（重複回傳 LIS、覆寫編輯人員） | **只能從影像檢視頁「儲存結果」開啟**；直接開網址回到檢體管理 | 正常操作流程不變 |
| A3 | 從報告頁返回清單時的選取 | 程式原意是選取剛處理的檢體，但實際上一律選清單第一筆（只有改為人工鏡檢會選取該筆） | **選取剛處理的檢體**（仍在清單上時），否則選第一筆 | 已拉片完成、簽核後返回清單 |
| A4 | 報告簽核頁 CBC 數值的前次報告（2026-10-25 Eden 提出） | CBC 數值區只有本次；LIS 前次報告只收 WBC、PLT 與分類 | 每個 CBC 項目下方加灰色小字「前次 x」；LIS 前次報告另收 RBC、Hb、HCT、MCV、MCH、MCHC（`lis.prevReport.cbc`）。模擬資料：25 筆都補上 CBC 前次值；非情境的 3 筆補上非白血球前次值（「其他發現」的前次欄看得到數值） | 報告簽核頁；留單判斷不變（這些項目沒有留單門檻） |
| A5 | 檢體管理清單的排序（第 4 章；2026-10-26 Eden 回報） | 只要有一顆膠囊打綠勾（數位閱片或需拉片確認完成）就排到最下面；例：實體作業模式點 H5080720647 的需拉片確認，還有血小板確認待辦卻沉到最下面。預設依分析時間新到舊 | **只有全部完成的才排最下面**，還有待辦的依選擇的欄位排序、留在原位；**預設依時效由久到短**（清單狀態的儲存鍵改為 `…-ui-state-v2`，舊的排序設定不沿用）。舊版原型也已同步修改 | 檢體管理清單的順序；規則判斷結果不變 |

## B. 舊版錯誤的修正（畫面上看得到）

| # | 項目 | 舊版 | 新版 |
|---|---|---|---|
| B1 | LIS 撤回（規則 15） | 開鎖簽核、隨簽核完成需拉片確認的檢體被撤回後，需拉片確認仍留著「完成」，檢體顯示已完成 | 撤回後一律回到剛進線的狀態 |
| B2 | 檢體管理「登出」按鈕 | 沒有作用 | 登出並回到登入頁 |
| B3 | 清單表頭「全選」勾選框 | 沒有作用 | 勾選／取消清單上所有列 |
| B4 | 報告簽核頁「當前操作者」 | 固定顯示範例人員 | 顯示目前登入的使用者 |
| B5 | 清單點膠囊後的頁尾訊息 | 被「已篩選 N 筆」蓋掉，看不到 | 正常顯示（例「血小板確認完成；已在 LIS 檢驗註記…」） |
| B6 | 清單重繪後的選取列 | 選取列的底色消失 | 保留選取 |
| B7 | 影像檢視頁網址的條碼不存在 | 改開清單第一筆（另一位病人），且可編輯、簽核 | 回到檢體管理 |
| B8 | 帳密打錯（瀏覽器還留著上次的登入資訊時） | 被當成「登入逾期」，跳出閒置登出訊息 | 顯示「帳號或密碼錯誤」 |
| B9 | 清單每 120 秒更新時效 | 已勾選的列被清掉 | 維持勾選 |
| B10 | 登入後回到原本要開的頁面 | 沒有作用，一律到檢體管理 | 回到原本要開的頁面（只接受本系統的頁面） |
| B11 | 情境模擬測試重新套用同一情境 | 上一位受試者的人員編輯值還留著（報告頁顯示舊結果） | 情境檢體的人員編輯結果全部清除 |
| B12 | 簽核後自動開下一筆，之後回到檢體管理（2026-10-25 Eden 回報） | 「簽核完成」提示在跳到下一筆時就排入、沒有顯示，等之後回到清單才跳出，還會蓋掉當下的提示（例：改為人工鏡檢後卻顯示前一筆「簽核完成」）；登出再登入也還在 | 只有簽核後直接回到清單才顯示「簽核完成」；登入、登出時清掉還沒顯示的提示（舊版原型也已同步修正，2026-10-25） |

## C. 不影響畫面的修正

| # | 項目 | 說明 |
|---|---|---|
| C1 | 閒置 30 分鐘自動登出 | 舊版沒有啟動；新版每個需要登入的頁面都會啟動，報告簽核視窗裡的操作也算有操作 |
| C2 | 兩個分頁同時操作同一筆檢體 | 舊版用該頁較舊的狀態整筆覆蓋（例：另一頁剛標記的血小板確認被蓋回未完成）；新版每次操作前先讀回最新狀態 |
| C3 | 登出時清除病人資料 | 處理狀態、人員編輯結果、LIS 回寫紀錄在登出時清除（共用電腦不留病人資料）。原型登入時本來就會重設，畫面沒有差別 |
| C4 | 編輯人員 | 正式環境（ENV＝production）也會記錄登入帳號；舊版只有模擬登入會記錄 |
| C5 | 改為人工鏡檢的 LIS 註記 | 由資料層的操作統一送出（舊版由畫面程式送出），任何畫面呼叫都不會漏掉 |

## D. 安全性（詳見 [`SECURITY.md`](SECURITY.md)）

| # | 項目 | 說明 |
|---|---|---|
| D1 | 畫面上的動態資料一律跳脫 | 病人姓名等資料不會被當成 HTML 執行 |
| D2 | 報告簽核視窗與外層頁面的通訊 | 只接受自己開的內嵌視窗的訊息；以網址開啟時只送給同一網站 |
| D3 | 登入後導向 | 只接受本系統的三個頁面；雙擊開啟（file://）時也擋下 `javascript:` 等網址 |
| D4 | 內容安全政策（CSP） | 每頁只允許建置時產生的程式執行，擋下被注入的程式與外部連線 |
| D5 | 開發者工具指令 | `__demo.withdrawFromLis()` 等只在原型（非正式環境）提供 |
| D6 | 套件弱點 | `npm audit` 0 項（Tailwind 3 間接依賴的 postcss-selector-parser 升級，建置結果逐字相同） |

## E. 技術改善（畫面不變）

| # | 項目 | 說明 |
|---|---|---|
| E1 | Tailwind CSS、字型改為本機檔案 | 不需連網；院內網路擋外部網站時畫面也正常 |
| E2 | 報告簽核頁加上 `<!DOCTYPE html>` | 舊版缺少，瀏覽器以相容模式顯示；新版畫面經截圖比對相同 |
| E3 | 使用教學 | 遇到未知的步驟資料時略過，不會中斷 |
| E4 | 移除沒有使用的訊息類型 | 舊版的 `specimenDataUpdated` 沒有任何頁面接收 |
| E5 | 字級與縮放的預先套用程式 | 由同一份規則（`src/ui/shared/preference-rules.ts`）產生，不再各頁各寫一份 |

## 驗證方式

| 項目 | 結果 |
|---|---|
| 規則對照（`tests/parity`） | 舊版程式唯讀載入，與新版跑同一組輸入：25 筆檢體 × 進線判斷、853 個操作步驟、門檻修改、LIS 撤回、人員編輯值計算，**輸出完全相同**（B1 的 14 個情況除外，已確認為修正） |
| 畫面對照（`tools/visual`） | 新舊版各跑同一套 77 個畫面的操作巡覽並逐張截圖比對：35 張完全相同；清單頁約 0.005% 像素為字型反鋸齒；其餘差異都是本文件列出的修正（報告頁操作者姓名 B4、頁尾訊息 B5、報告頁直接開啟 A2） |
| 回歸測試（`npm run test:e2e`） | 75 個畫面的 DOM 指紋與 12 張代表截圖；http 與雙擊開啟（file://）兩種方式都跑；另有 2 個操作流程測試（簽核後自動開下一筆、再改為人工鏡檢的提示，B12） |
| 單元測試（`npm test`） | 8 個檔案、119 項 |
